# Раздел «Сети»

## Назначение
Показывает все Docker-сети хоста карточками: имя, тип (создана compose-файлом или внешняя), драйвер,
число контейнеров и их имена. Нужен, чтобы понять, кто с кем находится в одной сети.

## Пользователи и доступ
- Любой, кто открыл дашборд; ролей нет.

## Точки входа
- Пункт верхнего меню «Сети».

## Основной сценарий
1. Пользователь нажимает «Сети» → открывается сетка карточек, над ней заголовок «Docker-сети · N»,
   где N — число сетей.
2. В шапке каждой карточки — имя сети и бейдж: «external» для внешних сетей, «compose» для остальных.
3. Внутри карточки две строки: «драйвер» со значением (например, `bridge`) и «контейнеров» с числом.
4. Если в сети есть участники, под строками показан список имён контейнеров отдельными тегами.
5. Данные обновляются периодическим опросом `/api/networks` без перезагрузки страницы.

## Альтернативные сценарии
- В сети нет контейнеров → список участников не показывается, в строке «контейнеров» стоит 0.

## Правила и ограничения
- Внешние сети (созданные вне compose-файла проекта, например `my_server_proxy_network`) помечаются
  бейджем «external» и визуально отличаются от обычных.
- Порядок карточек соответствует порядку, в котором сети вернул API; сортировки и фильтрации нет.

## Ошибки и крайние случаи
- Данные ещё не получены → показывается панель со строкой «загрузка…».
- Ответ получен, но сетей нет → панель со строкой «нет данных Docker».
- Ошибка запроса → в заголовке красным «ошибка: {текст}», ранее полученные карточки остаются.

## Данные
- Источник: `GET /api/networks` — массив сетей с полями `name`, `driver`, `containers`, `members[]`,
  `external`.
- Demo-набор: 15 сетей, есть и «compose», и «external»; например `docflow_default` — драйвер `bridge`,
  2 контейнера (`docflow-api`, `docflow-web`).
