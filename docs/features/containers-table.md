# Раздел «Контейнеры»

## Назначение
Показывает все Docker-контейнеры хоста одной таблицей: статус, имя, образ, сети, потребление CPU и RAM,
аптайм, число рестартов и публичный URL. Нужен, чтобы за один взгляд понять, что запущено, что упало
и что перезапускается.

## Пользователи и доступ
- Любой, кто открыл дашборд. Отдельных ролей нет.
- Если в `api/.env` задан `DASHBOARD_PASS`, до входа раздел недоступен: приложение показывает экран входа.
- В demo-режиме (`npm run dev:demo`, домены `demo.` / `infra.`) данные берутся из встроенного набора,
  API не опрашивается.

## Точки входа
- Пункт верхнего меню «Контейнеры». Приложение одностраничное: адрес не меняется, меняется активный раздел.

## Основной сценарий
1. Пользователь нажимает «Контейнеры» в верхнем меню → открывается панель со списком контейнеров.
2. В заголовке панели отображается строка «Контейнеры · N всего · M активны», где N — общее число
   контейнеров, M — число со статусом «работает».
3. Шапка таблицы содержит столбцы: имя, образ, сети, cpu, ram, аптайм, рестарты, url.
4. Каждая строка показывает: индикатор статуса, имя контейнера (под ним — назначение, если задано),
   технологию или образ, теги сетей, загрузку CPU в процентах, память в МБ, аптайм, число рестартов
   и ссылку «↗ открыть», если у контейнера есть публичный URL.
5. Данные обновляются периодическим опросом `/api/containers` без перезагрузки страницы.

## Альтернативные сценарии
- У контейнера нет публичного URL → в столбце «url» стоит «—».
- У контейнера не заполнены образ или аптайм → в соответствующем столбце стоит «—».
- Пользователь нажимает «↗ открыть» → URL контейнера открывается в новой вкладке.

## Правила и ограничения
- CPU выводится целым числом процентов со знаком «%», память — целым числом с суффиксом «MB»
  (значение округляется), рестарты — целым числом; при отсутствии значения выводится 0.
- Сети выводятся отдельными тегами, по одному на сеть; контейнер может входить в несколько сетей.
- Активными считаются контейнеры, чей статус распознан как «работает»; остальные учитываются только
  в общем числе N.
- Сортировки и фильтрации в текущей реализации нет, хотя SPEC их упоминает: список идёт в том порядке,
  в котором его вернул API.

## Ошибки и крайние случаи
- Данные ещё не получены → в теле таблицы строка «загрузка…».
- Ответ получен, но контейнеров нет → строка «нет данных Docker».
- Ошибка запроса к API → в заголовке панели красным выводится «ошибка: {текст ошибки}», при этом ранее
  полученные строки остаются на экране.

## Данные
- Источник: `GET /api/containers` — массив контейнеров с полями `name`, `purpose`, `image`, `tech`,
  `networks[]`, `cpu`, `mem`, `uptime`, `restarts`, `status`, `url`.
- Demo-набор: 48 контейнеров, 46 из них активны (в шапке — «Контейнеры · 48 всего · 46 активны»),
  у 8 контейнеров есть публичный URL со ссылкой «↗ открыть».
- Пример строки: `docflow-api`, образ `Node`, сети `docflow_default` и `my_server_proxy_network`,
  CPU `0.9%`, RAM `243MB`, аптайм `5д`, рестартов `0`, url `—`.
